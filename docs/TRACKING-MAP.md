# Підкладка карти (тайли)

Маршрут рейсу малює **MapLibre GL JS**, який лежить локально в `public/vendor/`
(CDN відключено правилами CSP). Підкладка — векторні тайли [Protomaps](https://protomaps.com)
у форматі [PMTiles](https://github.com/protomaps/PMTiles).

Працює **два режими**, і за замовчуванням нічого робити не треба:

| Режим | Коли | Що потрібно |
|---|---|---|
| **Онлайн (типово)** | `public/tiles/region.pmtiles` немає | нічого: сервер сам тягне тайли з архіву Protomaps |
| **Офлайн (опційно)** | файл `region.pmtiles` лежить на місці | один раз згенерувати файл (див. нижче) |

## Онлайн-режим: тайли «на вимогу»

Нічого не треба клацати й завантажувати вручну — після redeploy карта
піднімається сама.

1. Браузер просить `GET /tiles/{z}/{x}/{y}.mvt`.
2. Сервер дивиться в дисковий кеш `data/tilecache/<дата-збірки>/z/x/y.mvt`.
3. Якщо тайла немає — читає **лише потрібний шматок** планетарного архіву
   Protomaps по HTTP Range (139 ГБ не завантажуються, тягнеться кілька КБ).
4. Тайл кладеться на диск і віддається як `application/x-protobuf`
   з `Cache-Control: public, max-age=604800, immutable`.

Працює для **будь-якої точки світу**: тайл тягнеться за координатами, а не за
наперед визначеним регіоном. Рейс у Німеччині, Туреччині чи Казахстані
намалюється так само, як в Україні.

Додатково, коли веб-клієнт відкриває маршрут (`GET /api/trips/:id/track`),
сервер рахує прямокутник треку, сам добирає зум (щоб ділянка вклалася в
~160 тайлів) і **прогріває кеш у фоні** — поки користувач дивиться статистику,
тайли вже лежать на диску. Це і є та «автоматична» поведінка, коли карта
підвантажується там, де є точки.

### Налаштування (усі необов'язкові)

| Змінна | Типово | Що робить |
|---|---|---|
| `MAP_TILES` | `1` | `0` — повністю вимкнути підкладку |
| `MAP_TILES_URL` | — | свій PMTiles-архів замість збірки Protomaps |
| `MAP_BUILD_BASE` | `https://build.protomaps.com` | база щоденних збірок |
| `MAP_BUILD_LOOKBACK` | `5` | скільки днів назад шукати збірку, якщо сьогоднішньої ще немає |
| `MAP_MAX_ZOOM` | `14` | максимальний зум, який віддає сервер |
| `MAP_WARM_TILES` | `160` | стеля тайлів на один прогрів ділянки рейсу |
| `MAP_CONCURRENCY` | `8` | одночасних запитів до архіву |
| `MAP_CACHE_DIR` | `data/tilecache` | тека кешу (у Docker живе в томі `./data`) |
| `MAP_LOCAL_TILES` | `1` | `0` — ігнорувати локальний `region.pmtiles` і працювати онлайн |
| `MAP_TILES_NETWORK` | `1` | `0` — не ходити в мережу взагалі (лише дисковий кеш) |

### Скільки це їсть

Один тайл — 5–100 КБ (місто на z12 важче за ліс на z8). Кеш росте лише там,
де реально дивилися карту: типовий рейс Україною на z10 — це ~100 файлів, кілька
мегабайт. Кеш можна видаляти будь-коли: `rm -rf data/tilecache` — наступний
перегляд знову його наповнить.

## Офлайн-режим: локальний `region.pmtiles`

Потрібен, якщо сервер має працювати зовсім без інтернету. Локальний файл має
приоритет над онлайн-тайлами; `/api/tiles` тоді відповідає `"mode":"offline"`,
а клієнт читає архів через протокол `pmtiles://` (HTTP Range до статики).

Файл у git **не комітиться** (`tiles/*.pmtiles` у `.gitignore`).

### Варіант 1 — вирізати з готового Protomaps (без Docker, ~10 хв)

```bash
# 1. Бінарник pmtiles CLI
curl -L -o pmtiles.zip \
  https://github.com/protomaps/go-pmtiles/releases/latest/download/go-pmtiles_1.31.2_Windows_x86_64.zip
unzip pmtiles.zip

# 2. Полігон регіону (можна bbox: --bbox=minlon,minlat,maxlon,maxlat)
curl -L -o countries.geojson \
  https://raw.githubusercontent.com/datasets/geo-countries/master/data/countries.geojson

# 3. Оцінка розміру без завантаження
pmtiles extract https://build.protomaps.com/20261018.pmtiles ua.pmtiles \
  --region=ukraine.geojson --maxzoom=12 --dry-run

# 4. Сама екстракція
pmtiles extract https://build.protomaps.com/20261018.pmtiles ua.pmtiles \
  --region=ukraine.geojson --maxzoom=12 --download-threads=16
```

Перевірені цифри для всієї України (18.10.2026): **19 707 тайлів, 324 МБ, 6.5 хв**.
Дата в URL — дата збірки; беріть свіжу.

### Варіант 2 — planetiler + OpenMapTiles (потрібен Docker)

```bash
curl -O https://download.geofabrik.de/europe/ukraine-latest.osm.pbf   # 880 МБ
docker run --rm -v "$PWD:/data" \
  ghcr.io/onthego/planetiler-openmaptiles:latest \
  --input=/data/ukraine-latest.osm.pbf \
  --output=/data/region.pmtiles \
  --minzoom=5 --maxzoom=12 --bounds=22.1,44.3,40.3,52.5
```

Довше (десятки хвилин) і потребує 4–8 ГБ RAM, зате схема OpenMapTiles.
Фронтенд розуміє обидві схеми — див. «Як це працює в коді».

### Покласти файл і перевірити

```bash
mkdir -p tiles
cp ua.pmtiles tiles/region.pmtiles      # на хості; у Docker — том ./tiles
curl -s https://trip.bojumbohost.pp.ua/api/tiles   # {"mode":"offline","sizeMb":...}
```

Для локального запуску без Docker: `cp tiles/region.pmtiles public/tiles/`.

## Що буде, якщо підкладки немає зовсім

`GET /api/tiles` → `{"available":false,"mode":"none"}` і карта малюється на
однотонному фоні: суцільна синя лінія «рух авто», пунктирна помаранчева
«ходьба», сірі пункти «стан» і «немає сигналу», червоні точки — записи з GPS.
Масштаб, переміщення, зум і підказки працюють повноцінно — відсутність тайлів
не ламає жодної функції.

## Підписи (міста, вулиці, водойми)

Текст уже лежить у тайлах: `places` має `name` і `name:uk`, `roads` — назву вулиці,
`water` — назву моря чи річки. Тому підписи не вимагають нічого, крім **гліфів** —
PBF-файлів шрифту, з яких MapLibre малює символи.

- Гліфи лежать у `public/glyphs/Noto Sans Regular/` — 6 діапазонів (латиниця,
  латиниця-розширена, діакритика, **кирилиця**, кирилиця-доповнення, пунктуація
  зі знаком ₴), разом ~540 КБ. Взяті з `protomaps/basemaps-assets`, шрифт Noto Sans
  під SIL OFL 1.1 — `public/glyphs/OFL.txt`.
- У стилі: `glyphs: '/glyphs/{fontstack}/{range}.pbf'`, `text-font: ['Noto Sans Regular']`.
  Жодних CDN — CSP `connect-src 'self'` лишається чинним.
- Шари (`basemapLabelSpecs()`), знизу вгору: країни/регіони (великі літери,
  розріджені) → великі міста → міста середні → села → водойми → вулиці.
  Розмір залежить від зуму, а всередині категорії — від `population_rank`, тому
  Київ більший за Чорнобиль. Ієрархія зроблена **окремими шарами**, а не множником
  у `text-size`: MapLibre дозволяє `['zoom']` лише на верхньому рівні
  `step`/`interpolate`, і `['*', interpolate(...), ...]` падає з помилкою шару.
- Кожен об'єкт у тайлі має `min_zoom`; фільтр `min_zoom <= zoom` сам прибирає
  другорядне на дрібному масштабі, тому нічого не треба перелічувати руками.
- Назви беруться **українською**, якщо вона є (`name:uk`), інакше — місцевою.
  Для водія це читабельніше, ніж польські діакритики.
- Райони міст (`neighbourhood`, `suburb`, `quarter`) і урочища з шару сіл виключені:
  у Києві вони давали підписи на кшталт «Козине болото» розміром з місто.

## Як це працює в коді

| Файл | Роль |
|---|---|
| `public/vendor/maplibre-gl.js`, `maplibre-gl.css` | рендерер карти (~800 КБ, BSD-3) |
| `public/vendor/pmtiles.js` | протокол `pmtiles://` — лише для офлайн-файлу |
| `src/services/map-tiles.js` | пошук архіву, `getTile()`, дисковий кеш, `prefetch()`, `warmSegments()` |
| `src/routes/tiles.js` | `GET /api/tiles` (у т.ч. `ready` — чи дістався сервер до архіву), `GET /tiles/:z/:x/:y.mvt`, `POST /api/tiles/warm` |
| `src/lib/geo.js` → `decodePolyline()`, `bboxOfPoints()` | прямокутник треку для прогріву кешу |
| `src/routes/trips.js` → `GET /:id/track` | після відповіді запускає `warmSegments()` у фоні |
| `public/app.js` → `getTilesInfo()`, `basemapSource()` | вибирає джерело: `pmtiles://` або `/tiles/{z}/{x}/{y}.mvt` |
| `public/app.js` → `addBasemapLayers()` | малює підкладку: полігони — заливкою, лінії — лініями |
| `public/app.js` → `basemapLayerSpec()` | визначає тип шару за назвою source-layer (OMT і Protomaps) |
| `public/app.js` → `basemapLabelSpecs()` | підписи: країни, міста, села, вулиці, водойми |
| `public/glyphs/` | гліфи Noto Sans (кирилиця) — без них `symbol`-шари не малюють тексту |
| `public/sw.js` | `/tiles/*` навмисно **не кешує** — Range-запити ламають кеш SW |

## Обмеження, про які варто знати

1. **Потрібен інтернет на сервері** для онлайн-режиму. Якщо хост без виходу в
   мережу — генеруйте `region.pmtiles` і працюйте офлайн.
2. **Перший тайл чекає на архів.** Перший запит після старту витрачає ~1–3 с на
   визначення дати збірки Protomaps; далі це кешується на 6 годин.
3. **Плитки не кешуються сервіс-воркером** — у повністю офлайн-режимі браузера
   без попереднього перегляду підкладки не буде, буде лише трек.
4. **Якщо тайли не приїхали**, карта показує плашку «Підкладка недоступна» —
   клієнт через 6 с перепитує `/api/tiles` і дивиться на `ready`. Найчастіша причина —
   в контейнера немає виходу в інтернет; тоді в `/api/tiles` буде `"error"`.
5. **Підписи залежать від схеми тайлів.** Шари підписів звертаються до
   `places`, `roads`, `water` — це схема Protomaps. У файлі, згенерованому
   planetiler (схема OpenMapTiles), ці шари називаються інакше (`place`,
   `transportation_name`, `water_name`), тому підписи там не з'являться,
   а заливки й лінії — так.
6. **Немає підписів «щитків» доріг** (номерів у кружечках, як `М06`): для цього
   потрібні спрайт-зображення, яких ми не тримаємо. Номер дороги видно в `ref`,
   але він не малюється.
7. **Атрибуція.** Дані — © OpenStreetMap, тайли — Protomaps, шрифт — Noto Sans
   (SIL OFL 1.1, текст ліцензії в `public/glyphs/OFL.txt`). На карті показано
   «© OpenStreetMap»; при публічному доступі не прибирайте цей напис (вимога ODbL).

## Супутникова підкладка: чому не Google

Питання виникає регулярно, тому цифри й висновок зафіксовані тут.

**Легальний шлях до Google — це Map Tiles API**, і він вимагає включеного
білінгу та API-ключа. Що дають умови (перевірено 10.2026):

- безкоштовно **100 000 подій/міс** на SKU «2D Map Tiles», далі $0.60 за 1000;
- **але добова квота — 15 000 тайлів на проєкт на добу**. Це жорстка стеля,
  і вона важливіша за місячну;
- **кешування заборонене** — лише дотримання `Cache-Control` з відповіді;
  офлайн-використання заборонене прямо;
- обов'язковий **логотип Google Maps** і атрибуція з поля `copyright`
  (наприклад «Google, Maxar Technologies»);
- сторонні рендерери (MapLibre) — дозволені. Це єдиний пункт на користь.

Дві причини, чому це не підходить саме нам:

1. **Квота.** Україна цілком на z12 — це 28 773 тайли. Один такий погляд
   перевищує добовий ліміт Google удвічі.
2. **Кеш.** Уся схема тримається на `data/tilecache/`: тайл завантажується раз і
   живе вічно. З Google так не можна — кожне відкриття карти тягне все наново,
   і офлайн-режим зникає.

**Безключовий `mt1.google.com/vt?lyrs=s` — не варіант.** Це внутрішній ендпоінт
сайту Google Maps; жодної ліцензії на нього не існує. «Суто для власного
використання» не є винятком у ToS: угода потрібна для будь-якого використання
контенту, а не лише для публічного. До того ж з дата-центрових IP такі запити
періодично ріжуться, тож працюватиме воно нестабільно.

**Що можна натомість** (перевірено запитами, Київ, z14/z17):

| Джерело | Безкоштовно | Якість | Кешувати |
|---|---|---|---|
| Esri World Imagery (ArcGIS Location Platform) | 2 млн тайлів/міс | видно машини й дахи на z17 | ні |
| Mapbox Raster Tiles | 750 тис./міс | добра | ні |
| MapTiler | 100 тис./міс, **лише некомерційно** | добра | ні |
| Sentinel-2 (EOX / Copernicus) | без ліміту | 10 м/піксель — на z17 мило | **так** |

**Висновок.** Кешувати й показувати офлайн можна тільки з відкритими даними:
Protomaps/OSM (те, що вже є) і Sentinel-2. Комерційні знімки — Google, Esri,
Mapbox — ліцензійно дозволені лише як «онлайн, без кешу». Тому супутник, якщо
його робити, має бути окремим режимом на близькому зумі (z16–17, де один
квартал — це ~156 тайлів ≈ 4 МБ), а не заміною основної підкладки.

## Альтернативи, які відкинули

- **Варіант A** (свій рендер на сітці): вулиць не видно взагалі.
- **Варіант B** (Leaflet + OSM-тайли з чужого сервера): зовнішні запити до чужих
  серверів — ламає CSP і зливає маршрути водія. Саме те, від чого вся система
  уникає. Онлайн-режим ходить у мережу **з сервера**, а не з браузера водія.
- **Один великий файл на весь світ** (139 ГБ): не влізе ні в образ, ні в диск VPS.
