### 2026-10-18 — APK збирається; трекер справді відправляє дані (v1.3.2)
CI падав на компіляції Kotlin, тому `app-debug.apk` не існував узагалі. Плюс у сервісі
було три дефекти, через які трекер не працював би навіть після успішної збірки.

**Компіляція (`Polyline.kt`)**
- `put("pause_record_id", ...)` стояв **поза** блоком `apply`, тому ресивером був `TrackSegment`,
  а не `JSONObject` → `Unresolved reference: put` (`Polyline.kt:72:57`). Тепер `json.put(...)`,
  значення спершу збережено в локальну `val pauseId` (smart cast для властивості).

**Трекер (`TrackerService.kt`)**
- Вартовий рейсу крутився в **єдиному** потоці `worker` (`while ... SystemClock.sleep(30 с)`),
  тому всі відправки — сегменти маршруту й «Продовження руху» — стояли в черзі, поки триває рейс,
  і не виконувались ніколи. Винесено в окремий потік `trip-watcher`, `worker` вільний для HTTP.
- Після відповіді сервера з черги знімалась кількість `saved`, а `skipped` (уже збережені раніше —
  дедуплікація за `client_uuid`) лишались назавжди. Тепер знімається вся пачка: обидва стани
  термінальні (`saved + skipped > 0`).
- `maybeFlush` нічого не відправляв, коли черга вже повна (`pendingJson.size < MAX`) — тобто саме
  тоді, коли це потрібно найбільше. Умову прибрано.
- `ArrayDeque` черги чіпали три потоки (main, вартовий, воркер) → усі звернення під `segLock`;
  `pause` позначено `@Volatile`.

**Перевірка**
- Локальна збірка тим самим Gradle 8.7 / AGP 8.5.2 / Kotlin 1.9.24: `BUILD SUCCESSFUL`,
  `app-debug.apk` 5.9 МБ (`versionCode=1`, `minSdk 24`, `targetSdk 34`).
- CI після пушу: run `39116107541` — **BUILD SUCCESSFUL** за 1 хв 46 с, артефакт `trip-tracker-apk`.
- Кодек polyline перевірено round-trip'ом: `Polyline.encode` (Kotlin-алгоритм) → `decodePolyline`
  з `public/app.js` → координати збігаються до 5 знаків.
- `npm test` → **89/89**, `npm run check` → 39 файлів.

### 2026-10-17 — гарячий фікс міграції (v1.3.1)
- **Продакшн падав із `SqliteError: no such column: source`** (`initSchema`, `src/db/schema.js`).
  Причина: `CREATE INDEX ... idx_records_source ON records(source)` лежав у DDL, а на існуючій БД
  `CREATE TABLE IF NOT EXISTS records` не виконується — колонки `source` ще немає.
  Тести цього не бачили: усі створювали свіжу БД, де колонку додає CREATE TABLE.
- Виправлено: індекс перенесено після блоку `addColumnIfMissing`.
- Додано 7 тестів на шлях оновлення: `tests/schema-migration.test.js` (5) і
  `tests/schema-boot.test.js` (2) — піднімають застосунок на файлі зі старою схемою.
  Перевірено, що нові тести падають саме з `no such column: source` при поверненні баги.
- `npm test` → **89/89**.
